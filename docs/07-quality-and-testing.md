# PRD 07: Quality & Testing

## 1. Purpose

`kitty-pptx` sells fidelity and speed; both must be **measured, not asserted**. This document defines the test levels, the fixture corpus, the measurement protocols behind every NFR in [PRD 00](./00-system-overview.md) §5, and the gates that block a release. It exists because the previous revisions carried numeric targets with no defined measurement method — untestable targets are aspirations, not requirements.

## 2. Test Levels

| Level | Scope | Runs where | Gate |
| :--- | :--- | :--- | :--- |
| **L1 — Unit** | Color math, geometry generators (per-preset path output), EMU→px math, dash/cap mapping, chunker slicing, autonumber sequences | `cargo test`, every build | Merge-blocking |
| **L2 — Composition goldens** | Full-slide `RgbaSlide` output hashed/compared against committed reference images | CI (Linux container, fonts pinned) | Merge-blocking |
| **L3 — Protocol encoder goldens** | Byte-exact escape-sequence snapshots per driver: chunking, headers, `d=a` cleanup, `U=1` blocks, sixel banding, iTerm2 wrapping, half-block grids | CI (no terminal needed — encoders are pure) | Merge-blocking |
| **L4 — Live terminal smoke** | Real kitty / Ghostty / WezTerm windows: probe answers, image displays, scrollback survives scrolling, resize re-scales without flicker | Nightly + pre-release, scripted (terminal in GL/virtual mode where supported) | Release-blocking |
| **L5 — CLI end-to-end** | `export` fixture decks → compare PNGs; `dump`/`info`/`view` on fixture corpus incl. exit codes; stdin piping | CI | Merge-blocking |

Design note: L2/L3 test **against the contracts of [PRD 06](./06-component-interface-contracts.md)** — composition goldens hash `RgbaSlide` bytes; protocol goldens snapshot the byte stream the TtyWriter receives. Neither level needs a live terminal, which keeps the merge-blocking gates hermetic. L4 is the only level that touches a real terminal and is deliberately not merge-blocking (environment flakiness) but is release-blocking.

## 3. Fixture Decks

### 3.1 Composition Corpus (`tests/corpus/composition/`)
Synthetic decks, each generated by a checked-in script targeting **one** spec feature:

- One deck per T1 preset (PRD 02b §3.2) exercising default and non-default `adj` values.
- One deck per fidelity-matrix row (PRD 02d §2): each DEGRADED/PLACEHOLDER/OMITTED feature gets a deck that isolates it.
- One deck per text scenario: run-mixing, hanging bullets, autonumber families, autofit (`normAutofit` with stored scale, `spAutoFit`), RTL paragraphs, CJK (pinned Noto fixture font), vertical `vert270`.
- Edge geometry: zero-area shapes, off-slide shapes, 1-px strokes, overlapping z-order.

### 3.2 Fidelity Corpus (`tests/corpus/fidelity/`)
Real-world decks (permissively licensed, committed or fetched from a pinned source list) plus **reference renders** produced from the upstream browser viewer on the same decks. These drive the fidelity scoring of §5.

### 3.3 Robustness Corpus (`tests/corpus/robustness/`)
- Zip bombs, decompression-amplification files, truncated parts, malformed XML, deep nesting — seeded from upstream's published fuzz corpora (`fuzz/fuzz_targets/*`, `fuzz/dicts/ooxml.dict`).
- Password-protected and `.pptm` files (expect: typed error, exit 2, no crash).
- Empty presentation, 500-slide presentation, slide with 400 elements (expect: renders, within resource limits).

Policy: **any panic on any corpus deck is a release blocker** ([PRD 06](./06-component-interface-contracts.md) §8 panic policy).

## 4. Golden Image Regime

### 4.1 Reference Generation & Update
- Reference images are committed alongside fixtures (PNG per slide per target spec).
- Regeneration (`cargo test -- --bless`-style flag) is an explicit, reviewable action; CI fails on hash mismatch — it never auto-blesses.

### 4.2 Determinism Requirements
Goldens are valid because composition is deterministic (PRD 02a §4). CI therefore pins:
1. crate versions (`Cargo.lock` committed),
2. the bundled fonts (static, in-binary — the same bytes everywhere),
3. container font set for non-bundled fallbacks (DejaVu-only base image),
4. target specs per fixture (explicit, never terminal-derived).

### 4.3 Fidelity Scoring (fidelity corpus)
- Metric: perceptual diff (DSSIM or FLIP) between `kitty-pptx` render and the upstream reference render, per slide.
- Thresholds: `PASS ≤ 0.02` mean DSSIM; `REVIEW 0.02–0.06`; `FAIL > 0.06` on more than 10% of corpus slides blocks release.
- Score report is a CI artifact (per-slide heatmap + aggregate) so fidelity trends are visible over time.

### 4.4 Governance
Fidelity-matrix changes (PRD 02d §2) and corpus changes land in the **same** commit; a feature moving class (e.g. charts PLACEHOLDER → FULL) updates matrix, corpus decks, and goldens together.

## 5. NFR Measurement Protocols

Each target from [PRD 00](./00-system-overview.md) §5 gets a defined harness:

| NFR | Protocol | Fixture | Statistic | Pass |
| :--- | :--- | :--- | :--- | :--- |
| Startup < 120 ms | `time` from `execve` to first `present()` write complete (instrumented; `--report-timing` debug flag) | `typical-20` reference deck (defined in corpus: title + bullets + one image/slide, one chart, one table) | median & p95, n = 20, warm FS cache | both < 120 ms on reference hardware class (4-core, SSD) |
| Flip < 16 ms | keypress event read → `present()` written (staged path only) | `typical-20` | p99, n = 200 flips | < 16 ms |
| Slide render < 15 / 40 ms | compositor call → `RgbaSlide` returned | simple & complex corpus decks | p95, n = 50 | per PRD 02a §6 |
| Memory < 150 MB peak RSS | `getrusage(RUSAGE_SELF).maxrss` over a scripted full-deck walkthrough (all slides, sorter open, resize) | `typical-20` + one image-heavy deck | max | < 150 MB |
| Binary < 25 MB | stripped release build size | — | single number, pinned target triple | < 25 MB |

Measured numbers are reported per release; targets are re-baselined only through PRD 00 changes.

## 6. Continuous Integration Gates

**Merge-blocking** (every PR): L1, L2, L3, L5; `cargo clippy -D warnings`; `cargo fmt --check`; fuzz smoke (60 s per target, seed corpus).

**Nightly**: extended fuzz (1 h/target); L4 live-terminal matrix; fidelity corpus scoring with artifact upload; NFR measurement runs with trend dashboard.

**Release-blocking**: all of the above green on the release commit + release notes include the measured NFR table and fidelity score.
