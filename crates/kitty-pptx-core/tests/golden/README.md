# Golden-image E2E tests

Reference pixels and protocol streams that guard the entire deck-to-terminal
pipeline. Every PNG golden goes through the production seam used by the CLI:

```
.pptx -> DefaultPresentationLoader -> DefaultSlideCompiler::compile_in_deck
      -> TinySkiaRasterizer::rasterize -> RGBA8 -> PNG
```

## Corpus policy

Golden fixtures are generated **inside this repository** with a pinned tool
version. Every committed `.pptx` must have:

1. an in-repo generator script,
2. a pinned generator version,
3. a license note for the generator (and any embedded asset),
4. byte-stable output, or a documented normalization step.

The corpus currently contains one fixture, `pptxgenjs_sample.pptx`, generated by
`gen_pptxgenjs.js` with [PptxGenJS](https://github.com/gitbrent/PptxGenJS)
(MIT). The committed golden PNGs are renders of that generated deck.

## Layout

```
tests/
  golden_tests.rs              # core PNG golden harness + region invariants
  golden_support/mod.rs        # deck table, render cache, compare metrics
  golden/
    README.md                  # this file
    gen_pptxgenjs.js           # fixture generator (PptxGenJS 4.0.1)
    normalize_pptx.py          # byte-stable archive normalizer
    package.json               # pinned generator dependency
    package-lock.json          # reproducible install
    probe_png.py               # dev-only PNG/region colour probe
    decode_halfblock.py        # dev-only half-block ANSI decoder
    fixtures/pptxgenjs_sample.pptx
    png/pptxgenjs_sample/      # committed reference renders
```

## Generating the fixture

The generator uses PptxGenJS 4.0.1. It covers text runs, core and extended
preset shapes, tables, bar/line charts, embedded PNG images, notes and text
styling.

```sh
cd crates/kitty-pptx-core/tests/golden
npm ci
NODE_PATH="$PWD/node_modules" node gen_pptxgenjs.js fixtures/pptxgenjs_sample.pptx
python3 normalize_pptx.py fixtures/pptxgenjs_sample.pptx
```

PptxGenJS writes wall-clock timestamps into `docProps/core.xml`, its embedded
chart workbooks, and ZIP entry headers. `normalize_pptx.py` pins those dates,
sorts the archive entries and fixes every ZIP timestamp, so two generator runs
produce the same bytes. Verify before committing:

```sh
NODE_PATH="$PWD/node_modules" node gen_pptxgenjs.js /tmp/a.pptx
NODE_PATH="$PWD/node_modules" node gen_pptxgenjs.js /tmp/b.pptx
python3 normalize_pptx.py /tmp/a.pptx
python3 normalize_pptx.py /tmp/b.pptx
sha256sum /tmp/a.pptx /tmp/b.pptx   # must match
```

Do not commit `node_modules/` or a globally installed generator version; the
lockfile is the source of truth.

### PptxGenJS coverage

The pinned generator supports shapes, text, tables, charts, images, hyperlinks,
notes, shadows and solid fills. It does not emit gradient fills, OMML equations,
SmartArt diagrams, artistic image filters, EMF/WMF pictures, or full 3D shape
formatting. Those features are covered by unit tests rather than by this fixture
corpus.

## Fixed render spec

Each deck is rendered at a fixed `width_px = 800`; the height is derived from
the deck's slide aspect ratio and rounded deterministically:

| Deck | Slides | Golden size |
| --- | ---: | --- |
| `pptxgenjs_sample` | 6 | 800x450 |

The spec table (width and thresholds) is `DECKS` in `golden_tests.rs`.

## Regenerating goldens

After regenerating the fixture, or after an intentional renderer change:

```sh
UPDATE_GOLDENS=1 cargo test -p kitty-pptx-core --test golden_tests
```

The test writes every image under `tests/golden/png/<deck>/slide_NNN.png`,
prints each path, and still passes. Review the resulting image diff and commit
the new PNGs. Running without `UPDATE_GOLDENS` compares pixels.

Missing fixture files are a skip, not a failure. Missing golden PNGs for a
fixture that *is* present are a hard failure with a pointer back to this
command.

## Comparison thresholds

`golden_support::diff_metrics` computes, over all RGBA bytes:

- `mean_abs_diff`: mean absolute per-channel difference (0..=255 scale).
- `outlier_fraction`: fraction of pixels whose largest channel delta exceeds
  `channel_tolerance`.

Default policy: `mean_abs_diff <= 2.0`, `outlier_fraction <= 0.02` with
`channel_tolerance = 12`. `Thresholds::LOOSE` (`4.0 / 0.05 / 16`) remains
available for decks that exercise image filters or other intentionally variable
effects.

## Font dependency

Goldens are generated on Linux with **DejaVu Sans 2.37**
(`fonts-dejavu-core`) as the only installed family. The compiler substitutes
Calibri/Arial/Segoe UI with the best available system face, so:

- Goldens must be regenerated when the installed font family/version changes.
- CI images that render text-heavy decks need DejaVu Sans installed to match.
- Font-independent coverage lives in
  `pptxgenjs_slide1_solid_regions_match_ground_truth`. It asserts solid shape
  fills without any golden files.

## External renderer tier (opt-in)

`external/` contains a separate, expensive comparison against selected
LibreOffice QA decks rendered by `office-open-xml-viewer` through Playwright.
Fixtures are fetched at test time from a pinned LibreOffice commit with a
tree-filtered sparse checkout; reference PNGs are generated locally. Neither
the decks nor the reference images are committed, and the tier is not run by
`cargo test` or CI.

```sh
python3 crates/kitty-pptx-core/tests/golden/external/run.py
```

See `external/README.md` for caching, licensing, thresholds, and how to add a
fixture.

## Terminal-stream goldens

`kitty-pptx-display/tests/golden_stream_tests.rs` captures real driver output
by re-invoking the test binary in a child process (drivers write to stdout).
Those tests use a synthetic `RgbaSlide` and are independent of this fixture
corpus. See the module documentation in that crate for details.
